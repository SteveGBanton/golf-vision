**Context for AI Agent:**
We are building a monocular golf swing analyzer. The hardware consists of a high-speed global shutter camera placed on the floor, 14 inches from the ball, looking back at the golfer at a **45-degree angle (Yaw)**.
* **Goal:** Calculate Face Angle (Open/Closed), Club Path, and Attack Angle relative to the user's "Address Position."
* **Method:** We use ArUco markers on the club.
* **Current State:** Basic backend detects markers in 2D. Frontend displays raw JSON.

---

### Phase 1: Upgrade to 3D Pose Estimation
The current system tracks 2D pixel coordinates. We need 6-DOF (Degrees of Freedom) to measure angles and depth.

- [x] **Define Camera Intrinsics (Approximation):**
    - In `services/backend/main.py`, implement a helper to generate an approximate Camera Matrix and Distortion Coefficients based on the 640x480 resolution. (Note: Since we haven't done chessboard calibration, assume center principal point and standard focal length for a wide-angle M12 lens).
- [x] **Implement ArUco Board Support:**
    - Switch the detection logic from `detectMarkers` (single) to `estimatePoseBoard`.
    - **Geometry:** Define the board as a **2x1 GridBoard**.
    - **Metrics:** Assume two **30mm** markers separated by a **5mm** gap.
- [x] **Visualize Axes:**
    - Use `cv2.drawFrameAxes` to overlay the X, Y, Z axes on the video feed when the board is detected. This confirms we have a valid 3D orientation.

### Phase 2: Coordinate System Transformation
The camera is physically rotated 45 degrees relative to the target line. We must mathematically rotate the data back so "0 degrees" means "Square to Target."

- [x] **Implement Rotation Matrix Helper:**
    - Create a function `transform_to_world_coordinates(tvec, rvec)`.
    - Apply a **-45 degree rotation around the Y-axis** (Yaw) to align the camera's coordinate system with the real-world target line.
- [x] **Data Normalization:**
    - Convert `rvec` (Rodrigues vector) to Euler Angles (Pitch, Yaw, Roll) in degrees.
    - **Yaw** = Face Angle (Open/Closed).
    - **Pitch** = Lie Angle/Dynamic Loft.
    - **Z-Translation** = Club Path (In-to-Out vs Out-to-In).
    - **Y-Translation** = Attack Angle (Height relative to ground).

### Phase 3: Calibration Logic ("Address Zeroing")
We calculate swing metrics as a deviation from the user's starting position, not absolute world zero.

- [x] **Create State Manager:**
    - Implement a simple state machine in `main.py`: `IDLE` -> `CALIBRATING` -> `READY` -> `SWING_DETECTED`.
- [x] **Implement Calibration Endpoint:**
    - Add a backend function/WebSocket event to trigger "Set Zero."
    - When triggered: Capture the current `rvec` and `tvec` (averaged over 10 frames for stability). Store this as `reference_pose`.
- [x] **Calculate Delta:**
    - For every subsequent frame, calculate: `current_pose - reference_pose`.
    - Example: If `reference_yaw` is 45° and `current_yaw` is 47°, send `face_angle: +2.0` (2 degrees Open).

### Phase 4: Swing Trigger & Data Export
We need to capture the swing automatically and smooth the noisy data.

- [x] **Implement Impact Trigger:**
    - Define a virtual "Impact Line" (X-coordinate).
    - If the marker crosses this line with velocity > Threshold, freeze the data buffer.
- [x] **Implement Data Buffer:**
    - Maintain a rolling buffer of the last 20 frames.
    - When impact is triggered, package the 10 frames *before* and 5 frames *after* impact.
- [x] **Basic Interpolation:**
    - Since the club moves fast, the "Impact Frame" might be missing.
    - Write a function to find the two frames straddling the `X=0` (Impact) line.
    - Linearly interpolate the Face Angle and Path between these two frames to estimate the exact values at impact.
